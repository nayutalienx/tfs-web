# Правила проекта

- Общаться с пользователем на русском языке.
- Самостоятельный локальный REST-клиент TFS на Go; URL/проект/PAT задаются через браузерный контекст (/context). Внешние CLI и общие конфигурационные файлы не являются runtime-зависимостями.
- Не устанавливать постоянную службу и не включать автозапуск без отдельного указания.
- Использовать только синтетические тестовые данные, зарезервированные домены example/invalid и вымышленные идентификаторы. Не добавлять внутренние адреса, рабочие данные, персональные пути или секреты.
- Интерфейс компактный, настольный, в духе ImGui. Мобильная адаптация не требуется.
- Для небольших улучшений удобства разрешён простой нативный JavaScript (DOM и стандартные браузерные API).
- Не добавлять JS-фреймворки, сторонние JS-библиотеки, npm, бандлеры, транспиляцию и большие бандлы. JS отдавать локально, без CDN.
- Основные страницы и формы должны работать без JS; JS — прогрессивное улучшение, а не SPA.
- Контекст задаётся отдельно в браузере через /context: URL коллекции, проект и PAT. Хранить контекст только в зашифрованной AES-GCM HttpOnly SameSite=Strict cookie без серверного срока истечения; cookie на 400 дней продлевать при использовании. Ключ сохранять в пользовательском каталоге настроек с правами 0600, чтобы контекст переживал перезапуск; никогда не включать ключ в Git. Не использовать общий конфиг как неявный контекст. Не помещать открытый PAT в HTML-ответы, JS, Web Storage, URL или логи. Защищённые вложения отдавать через локальный Go-прокси; сохранять CSRF, Host-проверку, CSP и проверку изображений. При смене URL не переносить старый PAT автоматически.
- HTML рендерят серверные Go-шаблоны. Нативный JS улучшает формы, поиск и просмотр изображений; Node.js не нужен для работы сайта, только для необязательных тестов браузерного поиска.
- Не открывать вкладки/окна браузера без явного разрешения пользователя.
- Не изменять реальные данные TFS при проверке без прямого запроса пользователя; мутации проверять через mock-серверы.
