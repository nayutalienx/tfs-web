# TFS Web

Локальный веб-клиент для TFS / Azure DevOps Server: бэклог, репозитории, pull requests и Wiki. Самостоятельный REST-клиент на Go, серверные HTML-шаблоны и небольшой нативный JavaScript — без npm, SPA-фреймворков, CDN и сборки фронтенда.

**Это локальный инструмент одного пользователя, не публичный веб-сервис.** Интерфейс компактный, настольный, на русском языке. Проект независимый, не является продуктом Microsoft; совместимость со всеми версиями и процессами TFS не гарантируется.

## Быстрый старт

Нужен Go **1.26 или новее** и сетевой доступ к вашему TFS (при необходимости — VPN).

```sh
go run .
```

Откройте **http://127.0.0.1:18763**, затем задайте контекст:

- URL коллекции, например `https://tfs.example.com/DefaultCollection`;
- проект, например `DemoProject`;
- свой Personal Access Token (PAT).

Примеры в репозитории синтетические. Реальный адрес и учётные данные вводите только в локальном интерфейсе. Сервер обращается напрямую к REST API TFS; внешние CLI и конфигурационные файлы не нужны. Используется API 6.0, для комментариев — 5.0-preview.2.

Сборка самостоятельного бинарника:

```sh
go build -trimpath -o bin/tfs-web .
./bin/tfs-web
```

HTML и JS встроены в бинарник, запуск не зависит от рабочего каталога. Изменения шаблонов и скриптов требуют пересборки. Node.js не нужен для работы приложения.

## Контекст и безопасность

Кнопка справа сверху позволяет сменить URL, проект и PAT либо очистить контекст. Контекст хранится в зашифрованной AES-GCM cookie с `HttpOnly` и `SameSite=Strict`, **без срока истечения на сервере и с сохранением после перезапуска**. Браузеры ограничивают срок cookie: используется 400 дней с продлением при каждом обращении к защищённым страницам и при открытии контекста. После очистки cookie, длительного неиспользования или истечения самого PAT потребуется повторный ввод.

Ключ шифрования хранится в пользовательском каталоге настроек: на Linux — `$XDG_CONFIG_HOME/tfs-web/context.key` либо `~/.config/tfs-web/context.key`, права файла `0600`, нового каталога `0700`. Не публикуйте и не передавайте этот ключ: он позволяет расшифровать cookie. Удаление или замена ключа сбрасывает все контексты. На серверном диске PAT не сохраняется; открытый PAT не выводится в HTML, JavaScript, Web Storage, URL или логи. При смене URL старый PAT автоматически не переносится.

Контекст общий для вкладок одного браузерного профиля на одном hostname; `localhost` и `127.0.0.1` — разные контексты. Это не система многопользовательской авторизации.

Сервер слушает только `127.0.0.1:18763`, проверяет Host, CSRF и Origin для настройки контекста. Используются CSP, экранирование, allowlist-санитайзер HTML, проверка TLS и локальный прокси защищённых изображений. Cookie без `Secure` предназначена только для HTTP loopback. Локальный HTTP не обеспечивает защиту от вредоносных процессов на вашей машине.

**Не публикуйте приложение через reverse proxy, туннель, общий сервер или внешний интерфейс.** Для такого размещения нужны отдельная модель авторизации, HTTPS, управление ключами, защита исходящих запросов и аудит безопасности. Подробнее: [SECURITY.md](SECURITY.md).

Выдавайте PAT только необходимые права и небольшой срок действия. Чтение требует доступа к соответствующим Work Items, Code и Wiki; изменение — соответствующих прав записи. Слияние дополнительно ограничивается правами и политиками TFS. Не используйте административный токен без необходимости.

## Возможности

### Бэклог

- По умолчанию весь проект: до 100 последних изменённых элементов независимо от типа, исполнителя, даты и состояния. Можно переключиться на назначенные мне; группировка по состояниям, цветные типы и статусы, фильтры.
- Выбор спринтов / итераций проекта, включая прошлые, даты и переходы между соседними итерациями. Показываются элементы точного пути итерации; переходы сбрасывают дополнительные фильтры.
- Глобальный поиск по заголовку, описанию, критериям приёмки, шагам воспроизведения и точному ID. Не ищет в комментариях. Глобальный поиск охватывает всех исполнителей, любые даты и состояния.
- Дерево дочерних элементов, включая завершённые и вложенные; родительский элемент.
- Создание задач, PBI и ошибок с обязательными полями и необязательным родителем.
- Предзаполненный редактор: заголовок, статус, итерация, область, исполнитель, теги, активность, приоритет, оценки и трудозатраты, описание, критерии и воспроизведение. JSON Patch с проверкой ревизии защищает от перезаписи чужих изменений.
- Комментарии и просмотр скриншотов с увеличением, масштабом и переключением. Только растровые TFS-вложения через локальный прокси, без загрузки новых изображений.

Названия типов и полей ориентированы прежде всего на русскоязычный процесс TFS. Цвета статусов сопоставляются локально по названиям, а не загружаются из настроек процесса: задачи белые для состояния «Список задач», работа синим, приостановленные/проверка фиолетовым, завершённые зелёным. Неизвестные состояния нейтральные.

### Репозитории и pull requests

- Код, ветки, папки и текстовые файлы с номерами строк.
- Активные и слитые PR, списки проекта и отдельного репозитория. Личные авторские активные PR закреплены сверху, без дубликатов.
- Создание PR с проверкой опубликованных веток, связанные элементы бэклога и прикрепление выбранных собственных задач.
- Обсуждения, ответы и голосование от имени владельца PAT.
- Unified diff по сохранённой итерации и коммитам: добавление, удаление, переименование, номера строк. Первые 8 файлов показаны сразу, остальные открываются отдельно. Доступны версии до/после.
- Явное подтверждение слияния с проверкой исходного коммита. Используется `noFastForward`, без обхода политик, удаления исходной ветки и автоматического закрытия задач. Черновики, конфликты и незавершённая проверка блокируют действие. Авто-мерж и команды ботов не запускаются.

### Wiki

- Список Wiki, дерево документов, поиск по названиям с сохранением предков.
- Markdown с таблицами, списками, кодом и ссылками между страницами. Изображения из `/.attachments/` через защищённый прокси; внешние изображения и сырой HTML не исполняются.
- Редактирование с проверкой ETag; при конфликте введённый текст сохраняется в форме.
- Создание корневых, дочерних и соседних страниц с проверкой родителя и отсутствия целевой страницы. Удаление и перенос не реализованы.

### Нативный JavaScript

Без JS работают основные страницы и формы. JS добавляет fzf-подобный поиск по загруженным строкам, подсказки селектов, живой серверный поиск и просмотр изображений.

- `↑` / `↓`, `Enter` — выбор; `Esc` — закрыть или сбросить.
- `/` — быстрый фильтр; `Ctrl+K` — глобальный поиск.
- Серверные подсказки появляются через 300 мс; устаревшие запросы отменяются. Выбор задачи не прикрепляет её автоматически: нужна отдельная кнопка.
- Fuzzy-поиск работает локально, серверный поиск — по текстовым полям, не fuzzy по всей базе.

## Ограничения

- Бэклог, спринты, обычный поиск и живые подсказки — до 100 последних изменённых элементов на запрос, без автоматической загрузки остальных. Текст и итерация фильтруются в TFS до ограничения результатов; тип и состояние — по загруженным данным. Запрос — до 200 символов.
- Полный бэклог — обзор проекта, а не копия командной доски TFS: настройки команды, области и уровни бэклога не воспроизводятся. Доступ ограничен правами PAT; удалённые в корзину элементы не включаются.
- Ветки в обзоре и комментарии задач — первые 100; подсказки веток — до 1000. Общие списки PR и изменений имеют пагинацию.
- Дерево задач — до 2000 элементов и 50 уровней; Wiki — до 10000 страниц и 50 уровней. Достижение защитных пределов отмечается явно.
- Текстовые файлы — до 2 МиБ; изображения PNG/JPEG/GIF/WebP — до 10 МиБ. Бинарные файлы не показываются.
- Diff — суммарно до 128 КиБ и 4000 строк; большие файлы доступны отдельно без вычисления diff.
- После изменения rich-text поля записывается обычный текст с переносами; форматирование неизменённых полей сохраняется.
- Нет истории ревизий, редактора произвольных кастомных полей, WYSIWYG, подсветки синтаксиса, построчных комментариев diff и управления политиками.
- После таймаута изменения проверьте результат в TFS перед повтором: автоматических повторных попыток нет. Слияние может завершаться асинхронно.

## Проверки

```sh
go test -race ./...
go vet ./...
# Необязательно: Node.js 22+ для тестов поискового алгоритма
node --test static/search_test.cjs
```

Тесты используют локальные HTTP mocks, синтетические данные и не изменяют настоящий TFS. GitHub Actions выполняет те же проверки. Правила разработки — [CONTRIBUTING.md](CONTRIBUTING.md).

## Необязательная служба OpenRC

Для Linux с OpenRC есть установщик. По умолчанию он только собирает и устанавливает файлы — **не запускает службу и не включает автозапуск**. Выберите отдельного непривилегированного пользователя; приложение не требует root.

```sh
# Из корня проекта от выбранного обычного пользователя:
sh deploy/install-openrc.sh
# При установке от root явно задайте существующего непривилегированного пользователя:
# TFS_WEB_USER=appuser sh deploy/install-openrc.sh
```

Установщик использует `doas` или `sudo`, если запущен не от root. Настройки пользователя службы находятся в `/etc/conf.d/tfs-web`, бинарник — `/usr/local/libexec/tfs-web`, журнал — `/var/log/tfs-web/server.log`, ключ службы — `/var/lib/tfs-web/context.key`. Он не читает и не копирует учётные данные. Ручной запуск и служба используют разные ключи и не разделяют контексты автоматически.

При необходимости явно запустите службу и отдельно включите автозапуск (команды с правами root):

```sh
rc-service tfs-web start
rc-update add tfs-web default
# Остановка и отключение:
rc-service tfs-web stop
rc-update del tfs-web default
```

Перед стартом службы остановите ручной процесс, занимающий порт. Пересборка установленного бинарника требует перезапуска службы; браузерный контекст сохраняется при сохранении ключа.
